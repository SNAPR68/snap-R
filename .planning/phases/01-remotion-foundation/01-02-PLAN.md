  <files>

  <action>
Create `app/api/video/generate/route.ts` following existing API route patterns (see `app/api/enhance/route.ts` for auth and error patterns):

1. Add `export const dynamic = 'force-dynamic';` and `export const maxDuration = 60;` at top.

2. Import dependencies:
   - `NextRequest`, `NextResponse` from `next/server`
   - `renderMediaOnLambda` from `@remotion/lambda/client`
   - `createClient` from `@/lib/supabase/server`
   - `adminSupabase` from `@/lib/supabase/admin`
   - `generateVideoSchema` from `@/lib/validation/schemas`

3. Implement `POST` handler with this flow:
   a. **Authenticate**: `const supabase = await createClient()` then `supabase.auth.getUser()`. Return 401 if no user. (Note: `createClient()` is async in this codebase — must use `await`.)
   b. **Validate input**: Parse request body with `generateVideoSchema.parse(body)`. Wrap in try/catch — if ZodError, return 400 with validation error details.
   c. **Fetch listing**: Use `adminSupabase()` to query `listings` table, selecting `id, address, price, beds, baths` and joining `photos(processed_url)` where `listing_id` matches and `user_id` matches authenticated user. Return 404 if not found.
   d. **Validate listing has photos**: If `listing.photos` is empty or undefined, return 400 with "Listing has no photos".
   e. **Check env vars**: Verify all `REMOTION_*` env vars are present. If any missing, return 503 with "Video rendering not configured". Check: `REMOTION_AWS_REGION`, `REMOTION_AWS_ACCESS_KEY_ID`, `REMOTION_AWS_SECRET_ACCESS_KEY`, `REMOTION_LAMBDA_FUNCTION_NAME`, `REMOTION_S3_BUCKET_NAME`, `REMOTION_LAMBDA_SERVE_URL`.
   f. **Trigger Lambda render**: Call `renderMediaOnLambda()` with:
      - `region`: from env var
      - `functionName`: from env var
      - `serveUrl`: from env var
      - `composition`: `'TestVideo'`
      - `inputProps`: `{ listing: { address, price, beds, baths, photos: listing.photos.map(p => p.processed_url).filter(Boolean) }, aspectRatio: input.aspectRatio }`
      - `codec`: `'h264'`
      - `imageFormat`: `'jpeg'`
      - `maxRetries`: 3
      - `privacy`: `'public'`
      - `outName`: `` `${input.listingId}-${input.aspectRatio.replace(':', 'x')}-${Date.now()}.mp4` ``
   g. **Store in database**: Insert into `video_render_jobs` via `adminSupabase()`:
      - `user_id`: user.id
      - `listing_id`: input.listingId
      - `render_id`: renderId from Lambda response
      - `bucket_name`: bucketName from Lambda response
      - `status`: `'rendering'`
      - `input_props`: input (the validated Zod object)
   h. **Return**: `{ renderId, bucketName }` with status 200.

4. Error handling (REND-06 — always-complete semantics):
   - Wrap entire handler in try/catch
   - Catch block: `catch (error: unknown)` with `error instanceof Error` guard
   - If error is a Zod validation error (check `error.name === 'ZodError'`), return 400
   - For all other errors, return 500 with `{ error: message, code: 'RENDER_TRIGGER_FAILED' }`
   - Log error with `console.error('[video/generate]', error)`
   - Never throw unhandled — always return structured JSON

5. Type safety:
   - No `any` types. Use `unknown` for catch blocks.
   - Type the listing query result explicitly or let TypeScript infer from Supabase
   - Type the Lambda response: `{ renderId: string; bucketName: string }`

1. Create `app/api/video/status/route.ts`:

   a. Add `export const dynamic = 'force-dynamic';` at top.

   b. Import dependencies:
      - `NextRequest`, `NextResponse` from `next/server`
      - `getRenderProgress` from `@remotion/lambda/client`
      - `createClient` from `@/lib/supabase/server`
      - `adminSupabase` from `@/lib/supabase/admin`
      - `videoStatusSchema` from `@/lib/validation/schemas`

   c. Implement `GET` handler:
      - **Validate**: Extract `renderId` from `req.nextUrl.searchParams.get('renderId')`. Parse with `videoStatusSchema.parse({ renderId })`. Return 400 if missing/invalid.
      - **Authenticate**: `const supabase = await createClient()`, get user. Return 401 if no user.
      - **Verify ownership**: Query `video_render_jobs` via `adminSupabase()` where `render_id = renderId` AND `user_id = user.id`. Return 404 if not found (prevents users from polling other users' renders).
      - **If job already completed/failed in DB**: Return cached result immediately without calling Lambda (optimization — avoids unnecessary AWS API calls):
        ```
        if (job.status === 'completed') return { status: 'completed', videoUrl: job.video_url, renderTime: job.render_time_ms }
        if (job.status === 'failed') return { status: 'failed', error: job.error }
        ```
      - **Check env vars**: Verify `REMOTION_AWS_REGION` and `REMOTION_LAMBDA_FUNCTION_NAME` are set. Return 503 if missing.
      - **Query Lambda progress**: Call `getRenderProgress()` with `{ renderId, bucketName: job.bucket_name, functionName: env, region: env }`.
      - **Handle completion**: If `progress.done === true` and `progress.outputFile`:
        - Update `video_render_jobs` via `adminSupabase()`: set `status: 'completed'`, `video_url: progress.outputFile`, `render_time_ms: progress.timeToFinish ? Math.round(progress.timeToFinish) : null`, `cost_cents: progress.timeToFinish ? Math.round((progress.timeToFinish / 1000) * 0.5) : null`, `updated_at: new Date().toISOString()`
      - **Handle failure**: If `progress.fatalErrorEncountered === true`:
        - Extract error message: `progress.errors?.[0]?.message ?? 'Render failed with unknown error'`
        - Update `video_render_jobs`: set `status: 'failed'`, `error: errorMessage`, `updated_at: new Date().toISOString()`
      - **Return response**: JSON object with:
        - `renderId`: string
        - `status`: `'rendering' | 'completed' | 'failed'` (derive from progress.done / progress.fatalErrorEncountered)
        - `progress`: `progress.overallProgress` (number 0-1, only when rendering)
        - `videoUrl`: `progress.outputFile ?? null` (only when completed)
        - `error`: error message string or null
        - `renderTime`: `progress.timeToFinish ?? null` (milliseconds)

   d. Error handling (REND-06):
      - Wrap entire handler in try/catch
      - `catch (error: unknown)` with `error instanceof Error` guard
      - Return 500 with `{ error: message, code: 'STATUS_CHECK_FAILED' }`
      - Log: `console.error('[video/status]', error)`

   e. Type safety:
      - No `any` types
      - Type the video_render_jobs row explicitly with an interface or inline type
      - Type the progress response from `getRenderProgress` (use Remotion's exported types if available, otherwise define minimal interface)

2. Update `vercel.json`:
